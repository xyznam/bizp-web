# UID 보드 템플릿 규격

**이 문서는 화면군과 무관하다.** 어드민이든 사용자웹이든 모바일웹이든 같은 UID 보드 템플릿을 쓴다. 여기 있는 수치·색은 Figma 템플릿(`figma_template.pdf`)의 벡터·픽셀 정밀 판독값(px = pt 1:1)이며, 화면의 UI/GUI 디자인 규칙과는 별개 계층이다.

> 바꿔도 되는 것과 아닌 것
> - **바꾸지 않는다** — 색 팔레트, 헤더 구조, 콜아웃 기호 체계, 디스크립션 패널 폭 420, 표 행 규격
> - **인풋에 맞춰 정한다** — 디자인 영역 폭(따라서 보드 폭), 애플리케이션 칩 문구, Screen ID 체계
> - **미설계 영역** — 다중 뷰포트(§7)

## 1. 보드 골격

| 항목 | 값 |
|---|---|
| 보드 폭 | **디자인 영역 W + 디스크립션 패널 420**. admin은 1500 + 420 = 1920 |
| 보드 높이 | **가변** — 최소 1080, 콘텐츠에 맞춰 확장 |
| 보드 간 간격 (Figma 배치) | 120px |
| 헤더 높이 | 68px = 2행 × 34 (Screen Path 케이스 줄수만큼 2행이 확장될 수 있음) |
| 기본 폰트 | 프로젝트 표준 (admin은 Pretendard) |

**디자인 영역 폭 정하기** — 원본 화면이 렌더되는 실제 폭에 좌우 여백을 더한 값. admin은 1400px 뷰포트 화면을 1500 영역에 담았다. 화면 폭이 다르면 이 값을 다시 정하고 `board-policy.json`의 `board.designWidth`·`board.width`를 함께 고친다.

## 2. 헤더

**1행 (h34)** — 왼쪽부터:
- `Chapter` 라벨 셀: 94×34, 배경 `#EDEDED`, 검정 굵은 14px, 중앙 정렬
- 챕터 텍스트: x=101부터, 굵은 14px 검정. 형식 `N. 화면명`
- **애플리케이션 칩**: 125×20, 디자인 영역 우단 정렬, y=8, 배경 `#FFCD9F`, 흰색 굵은 14px 중앙. 문구는 `board.application` (admin은 `Web Admin`, 사용자웹이면 `User Web` 등). 한 화면이 복수 플랫폼에 걸치면 칩을 병렬로 둔다

**2행 (h34)** — 왼쪽부터:
- `Screen Path` 라벨 셀: 94×34, 배경 `#FEE500`, 검정 굵은 14px, 중앙 정렬
- 경로 텍스트: x=101부터, 굵은 14px. 형식 `Case n. 뎁스1 > 뎁스2 > 화면명 (Type/상태)` — 진입 경로 수만큼 줄 추가
- `Screen ID` 라벨 + 값: 디자인 영역 우측

행 구분선: 1px 검정. 헤더 아래부터 디자인 영역.

## 3. 디자인 영역

- 배경 흰색. 화면 콘텐츠는 좌우 여백을 두고 배치(원척 또는 축척, 여백 유지)
- 보조 상태(팝업·특수 케이스)는 메인 우측·하단 여백에 `*라벨` 주황 14px 캡션과 함께 병치

### 넘버링 기호 (콜아웃)

| 기호 | 형상 | 용도 |
|---|---|---|
| **영역 번호** | `#FF5700` 채움 원형 ⌀26, 흰 굵은 숫자 | 화면의 큰 구획(조회조건·목록·섹션 단위) |
| **영역 브래킷** | `#FF5700` 2px 선 — 상단 틱 20px→, 수직선, 하단 틱 20px→ | 영역의 수직 범위를 좌측 마진에서 감쌈. 칩은 브래킷 상단에 걸침 |
| **요소 번호** | `#FF9F6D` 알약 49×26, 흰 굵은 `1-1` | 영역 내 개별 요소(버튼·칩·건수 등) — 대상 요소 좌/우측에 인라인 |
| **점선 강조** | 주황 점선 박스 | 요소 영역 강조. 초록 점선+초록 알파벳 칩(`a`)은 별도 참조계 |

번호 체계: 영역 = `0,1,2,…` (위→아래), 요소 = `<영역>-<순번>` (`1-1`, `2-1`). 디스크립션 표의 Num과 1:1 일치해야 한다.

## 4. 디스크립션 패널 (폭 420 고정)

**헤더 행**: h30, 배경 검정, `Num`(폭 49) | `Description`(폭 371), 흰 굵은 14px 중앙. 패널 좌측 경계·행 구분선 1px `#808080`.

**※행** (헤더 바로 아래, 고정 순서): h34, Num 셀 채움색 + 흰 ※, 본문 셀 배경 `#E6E6E6`, 본문 텍스트 색 = Num 셀 색, 14px.

| 색 | 의미 |
|---|---|
| 빨강 `#D23838` | 추가 확인 필요한 사항 |
| 초록 `#1DB459` | 페이지 이동 또는 참고 문서 지시 / 공통 정의 참조 |
| 검정 `#000000` | 기타 공통 정의(공통 적용 스펙, API 등) |

**요구사항 행**: ※행 바로 아래, 번호 행 시작 전. 상세는 [description-rules.md](description-rules.md) §4-1.

**번호 행**: 배경 흰색, Num 셀 검정 굵은 14px 수직 중앙. 본문 1행은 컴포넌트/영역명 굵은 14px, 이하는 불릿 14px.

**코멘트 블록** (선택, 표 하단): 전폭 검정 배경, 흰 14px, `*Comment YYYY.M.DD.` + 자유 텍스트.

## 5. 본문 서술 문법

정본은 [description-rules.md](description-rules.md) §2. 요약:

- 라벨-값: `진행기간 : 이벤트 진행 기간` (콜론 앞뒤 공백)
- 열거: `바로적립 | Push적립 | 일반이벤트`
- 기본값: `(default : 전체기간)`
- 시스템 문구 원문: `alert("검색 조건을 하나 이상 입력해주세요.")`
- 주석: `※` 접두
- **빨강 텍스트** = 확인 필요·제약 경고 / **초록 텍스트** = 타 문서·링크 참조

## 7. 다중 뷰포트 — 미설계 영역

**이 템플릿은 단일 뷰포트를 전제로 설계됐다.** admin은 데스크톱 하나뿐이라 문제가 없었다. 반응형 화면군(PC + 태블릿 + 모바일)에 적용하려면 **보드 규격을 먼저 결정해야 하고, 그 결정은 이 문서에 없다.**

결정해야 할 것:

1. **뷰포트별 보드를 나눌 것인가, 한 보드에 병치할 것인가**
   - 나누면: 화면 하나가 보드 N개. Screen ID 체계에 뷰포트 축이 필요하고 보드 수가 N배가 된다
   - 병치하면: 디자인 영역 폭을 뷰포트 폭 합계로 키워야 한다. 보드 폭이 1920을 크게 넘어간다
2. **콜아웃 번호를 뷰포트 간에 공유할 것인가**
   - 공유하면 디스크립션 1벌로 끝나지만, 한쪽에만 있는 요소의 번호가 다른 쪽에서 빈다
   - 분리하면 디스크립션이 뷰포트 수만큼 늘어난다
3. **뷰포트 간 차이를 어디에 적을 것인가** — 별도 행 / 불릿 / 별도 보드
4. **IR을 뷰포트별로 뽑을 것인가** — `extract_ir.mjs`는 뷰포트 1개를 전제로 스크린샷·bbox를 만든다. 뷰포트마다 돌리면 IR 파일이 뷰포트 수만큼 생기고 매니페스트가 그것을 가리켜야 한다

권고: **1번을 먼저 정하고 파일럿 1화면으로 실물을 만들어 본 뒤** 나머지를 정한다. 문서상으로 결정하면 반드시 어긋난다. `probe_inputs.mjs`가 미디어 쿼리를 발견하면 이 절을 읽으라고 리포트에 적는다.
