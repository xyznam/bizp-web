# General 공통 정의 보드 규칙

화면마다 중복 서술되는 유형·상태·공통 규칙을 **General 카테고리**로 단일화한다. 개별 화면 보드는 General을 참조만 하고 정의를 반복하지 않는다.

## 1. 원칙

- **표로 만들 수 있는 것은 전부 표로.** 축(역할·상태·유형 등)과 값이 있는 것은 예외 없이 표
- 표로 전환되지 않는 정책·시나리오(조건 분기, 절차 서술, 예외 처리)는 같은 보드 안에 **텍스트 블록**으로 둔다
- 정의의 정본은 General이다. 화면 보드에서 같은 정의를 다시 쓰지 않고 초록으로 `General {ID} 참조`
- 한 화면에서만 쓰이는 값이라도 축이 공통이면 General 표에 넣고 `적용 화면` 열로 구분한다

## 2. 보드 규격

일반 화면 보드와 동일한 템플릿을 쓰되, 디자인 영역에 스크린샷 대신 표·텍스트를 직접 렌더한다 (매니페스트 `frame: "general"`).

- Chapter : `General — {그룹}`
- Screen Path : `Case 1. General > {그룹} > {보드명}`
- Screen ID : `{프로젝트접두}-GN-{순번 3자리}`
- 디스크립션 패널 : 적용 화면 목록(초록 ※), 미결·확인 필요(빨강 ※), 공통 근거(검정 ※), 번호 행에는 표별 사용 지침

## 3. 데이터 형식

`output/general/G-NN.json` — 디자인 영역 블록:

```jsonc
{
  "id": "G-01", "group": "권한·자격", "title": "매장 권한 역할·자격 체계",
  "blocks": [
    { "type": "table", "caption": "표 제목", "note": "표 앞 보조 설명(선택)",
      "columns": ["역할", "코드", "권한 범위", "적용 화면"],
      "rows": [["대표", "OWNER", "...", "01, 50, 52"]] },
    { "type": "text", "title": "표로 전환 불가한 정책",
      "paragraphs": ["..."], "bullets": ["..."] }
  ]
}
```

`output/descriptions/G-NN.json` — 우측 패널(기존 디스크립션 형식 그대로, `nocallout: true` 사용).

**열 너비는 브라우저 실측을 쓴다.** 코드로 추정하면 폰트·자간 차이로 반드시 어긋난다(`MANAGER`가 두 줄로 접히는 식). HTML 보드는 `table-layout:auto`로 두고 `measure_tables.mjs`가 실측값을 뽑아 Figma로 넘긴다.

## 4. 소관 매트릭스 — 병렬 작성의 필수 장치

General 보드를 여러 작성자가 병렬로 만들면 **같은 축을 두 보드가 각각 정의하는 충돌**이 반드시 발생한다. admin에서 실제로 일어났고, 축별 정본 보드를 고정하는 것으로 해결했다.

**절차**

1. 보드 초안이 모이면 **축 목록을 뽑는다** (역할, 상태, 자격, 결제 상태, 배치 상태 …)
2. 각 축의 **정본 보드를 하나 고정한다**
3. 정본이 아닌 보드는 그 축의 표·행을 삭제하고 초록 참조 1줄(`정의는 G-NN 참조`)로 대체한다

**정본 판단 기준** — 그룹 배정이 1순위, 같은 그룹 내에서는 **더 완전한 표를 가진 쪽**이 정본이다.

매트릭스는 프로젝트 산출물(`output/general/_ownership.md` 등)로 남긴다. admin의 실제 매트릭스는 [examples/admin-v3/README.md](../examples/admin-v3/README.md)에서 볼 수 있다.

## 5. 작성 규칙

- 문장부호 금칙(`·` `—`)은 [description-rules.md](description-rules.md) §2-1 그대로. 표 셀도 동일
- 표 열은 4~6개를 넘기지 않는다. 마지막 열은 관례상 `적용 화면`
- 값 설명은 한 셀 2줄 이내로 압축하고, 긴 조건은 텍스트 블록으로 내린다
- 화면 간 정의가 충돌하면 병합하지 않고 두 값을 각각 행으로 두고 충돌 사실을 빨강으로 표기한다

## 6. General 보드가 필요한가

**화면 수가 적으면(대략 10개 미만) 만들지 않는다.** General은 중복 서술의 비용이 참조의 비용을 넘을 때 이익이 된다. admin은 47개 실화면에서 14개 General 보드가 나왔다. 화면군이 작으면 공통 정의를 각 화면의 검정 ※행으로 두는 편이 읽기 쉽다.
