# 디스크립션 작성 규칙

시각 규격은 [board-template.md](board-template.md) §4·§5. 이 문서는 **무엇을 어떻게 쓸 것인가**를 정한다.

**화면군 의존도** — §1~§4는 화면군과 무관하다. §5의 *원천 슬롯*만 프로젝트마다 다르게 채운다.

## 0. 규칙의 지위 (메타 규칙)

이 문서의 규칙은 **관찰에서 나온다.** 추정으로 만들지 않는다.

- **확정** — 서로 다른 보드에서 **2회 이상** 같은 방향으로 관찰된 것
- **잠정** — 1회 관찰. 다음 회차에서 재관찰되면 확정, 반증되면 철회
- **확인 대기** — 의도가 갈리는 것. 사용자 확인 전까지 기존 규칙 유지

> 1개 표본에서 구조 규칙을 일반화하지 않는다. 실제로 "불릿 1뎁스 평면화"를 1회 관찰로 확정했다가 다음 보드에서 반증되어 철회한 사례가 있다. 규칙 승격·철회 절차는 [../workflow/rule-feedback.md](../workflow/rule-feedback.md).

## 1. 행 구성 원칙

- **번호 행 = 화면의 의미 단위 1개.** 영역(조회조건·목록·폼 섹션) 단위로 크게 자르고, 영역 내 개별 컨트롤은 그 행의 불릿 또는 `N-n` 요소 행으로 내린다
- 행 제목은 컴포넌트/영역명 그대로 (`조회조건`, `기본정보`). 문장 금지
- 번호는 화면 위→아래, 좌→우 순. 콜아웃 번호와 디스크립션 Num은 반드시 1:1
- `N-n` 요소 행은 부모 영역 바로 아래 배치 (`1` → `1-1` → `2`)
- `etc` 행: 번호로 가리킬 수 없는 항목의 모음
- **숨은 상태 서술 행**: 디스크립션 JSON에 `"nocallout": true`를 명시 선언하면 콜아웃 없이 허용. 선언 없는 콜아웃 누락은 검증 실패

### 1-1. 조건부 UI는 글로 대신하지 않는다 (잠정)

라디오 분기·단계 전환·상태별 노출처럼 특정 상태에서만 나타나는 UI는 서술로 대체하지 말고 **그 상태의 화면을 보드에 싣는다.** 부속 프레임 캡처가 빈 입력 상태로 잡히는 경우도 같다 — 값이 채워진 상태를 캡처한다.

## 2. 불릿 서술 문법

| 패턴 | 형식 |
|---|---|
| 라벨-값 | `진행기간 : 이벤트 진행 기간` — 콜론 앞뒤 공백 |
| 선택지 열거 | `바로적립 \| Push적립 \| 일반이벤트` |
| 기본값 | `(default : 전체기간)` `(default : unchecked)` |
| 시스템 문구 | `alert("검색 조건을 하나 이상 입력해주세요.")` — 원문 그대로 |
| 동작 | `선택 시 ~로 이동` `~ 노출` `hidden 처리` |
| 제약 | `85자 제한` `(' " 입력불가)` |
| 주석 | `※` 접두 |
| 구성 나열 | `구성 : 브랜드명, 상품명, 상품 가격 정보` |

**들여쓰기는 최대 2단.** 3단이 필요하면 행을 쪼갠다.

> 이력: 2026-08-06 회차 1에서 "1뎁스 평면화"를 확정했으나 회차 2·3에서 하위 불릿이 정상적으로 쓰인 것이 확인되어 **철회**했다. 최대 2단 규칙이 유효하다.

### 2-1. 문장부호 금칙

- **`·`(가운뎃점) 금지.** 나열 연결은 의미에 따라 `/` 또는 `,`. 용어 병기 괄호 안도 동일: `보유 매장 권한(역할/자격)`. 유일한 예외는 **화면 문구 원문 인용**(칩 라벨, alert 문구 등)
- **긴 줄표 `—` 금지.** 앞 표현에 `.`를 찍고 이어 쓰거나 `:` 또는 `( )`로 표기한다

`lint_descriptions.mjs`가 이 두 가지를 결정론으로 검사한다.

## 3. 색 의미론 (본문 텍스트)

- **빨강** — 확인 필요·제약 경고·개발 검토 필요
- **초록** — 타 문서·페이지·파일 참조
- 검정 — 그 외 전부

### 3-1. 산출물의 빨강 ≠ 리뷰의 빨강 (확정)

사용자가 **Figma에서** 본문 불릿을 빨강으로 칠하면 그것은 산출물의 색 의미론이 아니라 **"이 줄이 개정분이니 반영하라"는 작업 지시**다.

- 표시된 줄을 빠뜨리지 않는 것이 계약이다
- 반영 후 산출물에는 **검정으로 렌더한다.** 같은 색에 두 의미를 겹치면 보드를 읽는 사람이 구분할 수 없다

### 3-2. `#태그` = 사용자 작업 지시 (확정)

수정본에 `#휴면해제 버튼 필요`, `#버튼추가`, `#2일 때의 화면추가 필요` 같은 `#` 접두 문구가 있으면 디스크립션 본문이 아니라 **작업 지시**다. 지시 대상은 디스크립션일 수도, **화면 원본**일 수도, **캡처 상태**일 수도 있다. 판별해서 처리하고 산출물에는 태그를 남기지 않는다.

## 4. ※행 (표 상단 고정)

| 순서 | 색 | 용도 |
|---|---|---|
| 1 | 빨강 `#D23838` | 추가 확인 필요한 사항 (미결 대장의 해당 화면 항목) |
| 2 | 초록 `#1DB459` | 진입 경로 · 부속 보드 목록 |
| 3 | 검정 `#000000` | 기타 공통 정의(공통 스펙·API 등) |

해당 없는 색의 ※행은 **행 자체를 생략**한다. 본문에 `해당 없음`을 쓰지 않는다.

**초록 ※행의 범위 (잠정)** — `진입 경로`와 `부속 보드 목록` 두 가지만. 타 화면 위임과 공통정의 참조는 해당 번호 행의 초록 불릿에서 다루고 ※행에 중복 기재하지 않는다.

**빨강 ※행 유지 여부는 확인 대기.** 사용자 수정본에서 2회 빠졌으나 그것이 규칙 변경인지 리뷰용 편집인지 확정되지 않았다. 현행은 **유지**.

## 4-1. 요구사항 행

※행 바로 아래, **번호 행이 시작되기 전**에 `요구사항` 셀을 둔다.

- 렌더 형식: `{ID} : {본문}` 한 줄 (확정)
- 요구사항 문서의 판정 기호·근거 열은 옮기지 않는다. 과잉 후보는 요구사항이 아니므로 제외
- 부속 보드는 그 부속이 수행하는 요구사항만 기재. 해당 항목이 없으면 행 자체를 생략
- JSON: `"requirements": [ { "id": "R1", "text": "…" }, … ]`
- 문장부호 금칙(§2-1) 적용

**ID 정본 순위 (확정)**

```
사용자 최근 수정본  >  요구사항 원천 문서  >  자동 생성본
```

사용자가 Figma에서 요구사항 ID를 바꿨다면 그것이 정본이다. 원천 문서와 어긋나면 어긋남을 기록하되 사용자 값을 쓴다.

## 4-2. 근거 ID 병기 — 좌표성은 유지, 이력성은 제거 (확정)

| 종류 | 예 | 처리 |
|---|---|---|
| **좌표성** — 독자가 실제로 따라가는 것 | `BZP-AD-PG-001`, `메인 보드 4-1`, 부속 보드 ID | **유지** |
| **이력성** — 작성 과정의 근거 | `16 DUP-01 해소분`, 내부 결정 이력 | **제거** |

## 5. 프로젝트별로 채우는 것 — 원천 슬롯

여기가 화면군마다 달라지는 유일한 부분이다. [policy-mapping.md](policy-mapping.md)에서 실제 문서에 배정한다.

| 슬롯 | 역할 | 디스크립션에서의 쓰임 | admin의 대응 |
|---|---|---|---|
| **A. 화면 원천** | 보이는 문구·컨트롤·상태의 정본 | 번호 행 불릿의 사실 | static HTML |
| **B. 요구사항** | 화면이 무엇을 해내야 하는가 | 요구사항 행 | `38_admin_requirements.md` |
| **C. 공통 정책** | 조건·수치·예외의 상세 | 번호 행 불릿 + 검정 ※행 | `37_admin_operation_policy.md` |
| **D. 미결 대장** | 아직 정해지지 않은 것 | 빨강 ※행 | `39_open_items.md` |
| **E. IA** | Chapter·경로·Screen ID | 헤더 메타 | `beeple_admin_IA_launch_v3.xlsx` |

**슬롯이 비어 있을 때** — 없는 슬롯을 지어내지 않는다. 빈 슬롯은 그 자체가 보고 대상이다.

- B가 없으면 → 요구사항 행을 생략하고, 요구사항 정의가 없다는 사실을 기록한다
- D가 없으면 → 빨강 ※행이 비는 게 아니라 **미결을 추적하는 수단이 없다**는 뜻이다. 작업 중 발견한 미결을 모을 장부를 새로 만들 것을 제안한다
- E가 없으면 → 가안 Screen ID 체계를 세우고 빨강 ※행에 채번 필요를 기록한다

## 6. 공통 규칙

- 추론으로 채운 정책의 표기 (**잠정**): 현행은 불릿 끝에 `(추론 작성)` 명시. 사용자 수정본에서 1회 전량 소거된 관찰이 있으나 1회 관찰이므로 확정하지 않는다. 폐기가 확정되면 렌더에는 싣지 않고 JSON에 `inferred: true` 플래그로만 추적한다
- 공통 정책은 매 화면 반복하지 않는다. 검정 ※행에서 1줄 참조로 처리하고, 정의 본체는 General 보드에 둔다([general-boards.md](general-boards.md))
- **부속 화면(모달/드로어/플로우 팝업)은 별도 보드로 분리.** 메인 보드의 트리거 행에서 부속 보드 Screen ID를 초록으로 참조한다. 프로토타입 전용 헬퍼는 보드화하지 않는다
- 여러 화면에 동일 주입되는 공통 팝업은 보드를 1개만 두고 각 화면에서 초록 참조한다. 화면별로 복제하지 않는다
- 코멘트 블록: 자동 생성 시 `*Comment YYYY.M.DD.` 1행 + 생성 근거/보완 이력. 사람이 수동 기재할 경우 형식 자유
