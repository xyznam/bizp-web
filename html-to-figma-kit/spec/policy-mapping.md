# 원천 → 디스크립션 매핑 규칙

화면과 정책 문서를 대조해 디스크립션 행을 만드는 절차. 슬롯 정의는 [description-rules.md](description-rules.md) §5.

## 1. 슬롯 배정 (프로젝트 시작 시 1회)

작업 시작 전에 이 표를 채운다. **채우지 못한 슬롯은 빈 채로 두고 그 사실을 기록한다.** 억지로 배정하면 근거 없는 서술이 산출물로 간다.

| 슬롯 | 이 프로젝트의 문서 | 비고 |
|---|---|---|
| A. 화면 원천 | | 단일파일 static HTML이어야 한다 |
| B. 요구사항 | | 없으면 요구사항 행 생략 |
| C. 공통 정책 | | |
| D. 미결 대장 | | 없으면 새로 만들 것을 제안 |
| E. IA | | 없으면 가안 ID 체계 |

**우선순위** — 충돌 시 **A(최신 화면)가 이긴다.** 다만 문서의 명시적 백엔드 정책(권한, 감사, 보존 기간 등 화면에 안 보이는 것)은 유지하고, 충돌 사실을 빨강 불릿으로 기록한다. 화면에 없는 컨트롤을 디스크립션이 만들어내지 않는다.

## 2. 행 도출 절차 (화면당)

1. **화면을 영역으로 자른다.** 잘린 영역이 곧 번호 행이다. 자르는 축은 화면군의 표준 골격을 따른다
   - 목록형 화면: 헤더/전역 액션 → 지표 → 조회조건 → 목록 → 부속(모달·드로어)
   - 폼형 화면: 헤더 → 섹션별 입력군 → 액션 → 부속
   - 화면군이 다르면 그 화면군의 반복 골격을 먼저 찾아 고정한다. 화면마다 다른 축으로 자르면 보드 간 비교가 불가능해진다
2. **B(요구사항)의 항목을 영역에 배정한다.** 근거 요소 정보가 있으면 그것이 어느 영역인지 알려준다
3. **영역별 컨트롤을 A(화면)에서 확인하며 불릿화한다.** 필터 옵션·기본값은 추측하지 말고 실제 `<option>`·`checked`·placeholder에서 읽는다
4. **C(공통 정책)에서 그 영역에 걸리는 수치·조건을 붙인다**
5. **D(미결)에서 그 화면 항목을 찾아 빨강 ※행에 올린다.** 본문 특정 행에 속하면 그 행에 빨강 불릿도 추가
6. **다른 화면으로 위임된 기능은 초록 불릿**로 처리한다
7. 근거가 어느 슬롯에도 없는 서술은 표기 규칙([description-rules.md](description-rules.md) §6)에 따라 처리한다

## 3. 부속 화면 처리

- 메인 + 부속 세트가 한 화면 단위
- 시각적으로 독립 렌더 가능한 모달·드로어는 **별도 보드**. 라벨은 `<메인라벨>__<부속ID>` 형식
- 단순 확인 팝업(confirm)은 별도 보드 없이 트리거 행의 불릿으로: `선택 시 confirm("...") 노출`
- 공통 팝업 정의가 있으면 참조만: 초록 불릿 `공통팝업 <ID> 적용`

## 4. 금지

- 새 화면 ID·새 요구사항 창작
- 요구사항 문서의 판정 기호·표 형식을 기계적으로 복사 (디스크립션은 완성형 서술)
- 공통 정책 전문을 매 화면에 중복 (검정 ※행 1줄 참조로)
- 상충 상태의 무단 병합 — 충돌은 기록하고 사용자 확인

## 5. 정책 추출 스크립트를 쓸 것인가

`examples/admin-v3/scripts/extract_policy.mjs`는 admin의 md 문서 4종에서 화면별 항목을 긁어 초안 JSON을 만든다. **이 스크립트는 admin 문서의 마크다운 구조에 종속된다.** 새 화면군의 원천이

- **같은 형태의 구조화 문서**(화면별 섹션 + 표)라면 → 헤딩 패턴만 바꿔 재사용
- **비구조화 문서**(산문, 슬라이드, 회의록)라면 → 스크립트를 만들지 말고 AI가 직접 읽어 §2 절차를 수행한다. 구조가 없는 것을 정규식으로 긁으면 조용히 빠뜨린다
- **문서가 아예 없다면** → 화면(A)만으로 쓰고, 정책 근거 부재를 빨강 ※행으로 전량 기록한다
