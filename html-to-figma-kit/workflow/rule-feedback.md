# 규칙 역류 — 사용자 수정본에서 규칙을 얻는다

자동 생성한 디스크립션을 사용자가 Figma에서 손본다. **그 손질이 규칙의 원천이다.** 이 루프를 돌리지 않으면 같은 지적을 화면 수만큼 반복해서 받는다.

## 원칙

- **규칙은 관찰에서 나온다.** 추정으로 규칙을 만들지 않는다
- **의도가 갈리는 항목은 `확인 대기`로 두고** 사용자 확인 후 확정한다
- **1개 표본에서 구조 규칙을 일반화하지 않는다**

## 승격 기준

| 등급 | 조건 | 처리 |
|---|---|---|
| **잠정** | 1회 관찰 | 기록만. 규칙 문서에 반영하지 않음 |
| **확정** | 서로 다른 보드에서 **2회 이상** 같은 방향 | `spec/description-rules.md`에 반영 |
| **철회** | 반증 관찰 | 잠정/확정을 내리고 반증 사실을 기록 |
| **확인 대기** | 의도가 갈림 | 사용자에게 묻는다. 답 전까지 기존 규칙 유지 |

**확정된 것도 철회될 수 있다.** admin에서 "불릿 1뎁스 평면화"를 1회 관찰로 확정했다가 다음 두 보드에서 반증되어 철회했다. 그 사고 이후 2회 기준이 생겼다.

## 절차

1. **대조** — 자동 생성본 JSON ↔ 사용자 수정본(Figma 캡처). 차이를 전부 나열한다
2. **분류** — 각 차이를 셋 중 하나로
   - **내용 변경** — 화면이 바뀌었거나 사실이 틀렸다. 규칙이 아니다
   - **표기 규칙 변경** — 같은 내용을 다르게 적었다. 규칙 후보
   - **작업 지시** — `#태그`나 빨강 마킹. 규칙이 아니라 해야 할 일
3. **기록** — 회차별로 관찰 표를 남긴다 (아래 형식)
4. **승격 판정** — 기준표대로
5. **반영** — 확정분만 `spec/description-rules.md`에 반영하고, 반영 후 기존 산출물을 재생성할지 판단한다

## 기록 형식

프로젝트의 `DESCRIPTION_RULES_DELTA.md`에 회차별로 쌓는다.

```markdown
## 회차 N — YYYY-MM-DD · <보드 라벨>

- 대조 대상: 자동 생성본 <경로> ↔ 사용자 수정본(Figma 캡처)
- 판독 한계: <전량 대조를 못 했으면 그 사실을 명시>

### D-n. <한 줄 요지>

| | |
|---|---|
| 자동 생성본 | … |
| 사용자 수정본 | … |
| 발생 | N건 |
| 상태 | 잠정 / 확정 / 철회 / 확인 대기 |

**규칙 후보** — …

> 현행 규칙과의 충돌: … (있으면)
```

**판독 한계를 반드시 적는다.** 캡처가 조밀해 전량 대조를 못 했으면 "구조/표기 층위만 봤다"고 쓴다. 안 쓰면 나중에 안 본 것을 본 것으로 착각한다.

## 자주 나오는 유형 (admin 실측)

| 유형 | 예 | 교훈 |
|---|---|---|
| 작성 메타 제거 | `(추론 작성)` 소거 | 독자에게 판단 재료가 아닌 것은 본문에서 뺀다. 추적은 별도 채널로 |
| 근거 ID의 두 종류 | `BZP-AD-PG-001`은 유지, `16 DUP-01 해소분`은 삭제 | **좌표성은 유지, 이력성은 제거** |
| 리뷰 채널의 색 | 본문 불릿 빨강 | 산출물의 색 의미론이 아니라 "이 줄이 개정분" 지시 |
| `#태그` | `#버튼추가` | 디스크립션이 아니라 **화면 원본** 또는 **캡처 상태**를 고치라는 지시일 수 있다 |
| ※행 축약 | 초록 ※행에서 위임 서술 삭제 | ※행의 담당 범위를 좁히라는 신호 |
| 캡처 상태 결함 | "미입력 상태 스냅샷인데 값이 채워진 화면이 필요" | 디스크립션 규칙이 아니라 IR 추출 설정 문제 |

마지막 두 줄이 중요하다. **사용자 수정본이 항상 디스크립션 규칙을 말하는 것은 아니다.** 파이프라인의 다른 단계(화면 원본, IR 추출 설정, 캡처 방식)를 가리키는 경우가 섞여 있고, 그것을 디스크립션 규칙으로 오독하면 엉뚱한 곳을 고치게 된다.

## 반영 후

확정 규칙을 반영하면 **기존 산출물이 그 규칙에 어긋난 상태로 남는다.** 세 선택지가 있다.

| 선택 | 언제 |
|---|---|
| 전량 재생성 | 규칙이 표기 층위이고 스크립트로 일괄 처리 가능할 때 |
| 다음 손질 때 반영 | 규칙이 사소하고 재생성 비용이 클 때 |
| 그대로 둠 | 이미 인도된 산출물. 재생성이 오히려 혼란을 부를 때 |

어느 쪽이든 **선택을 기록한다.** 안 하면 나중에 왜 보드마다 표기가 다른지 아무도 설명하지 못한다.
