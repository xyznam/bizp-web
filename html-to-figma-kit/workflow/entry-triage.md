# 진입 판정 — 어디서부터 시작할 것인가

새 화면군에 이 파이프라인을 붙일 때, **이미 있는 것을 살릴지 다시 만들지**를 정한다. 이 판정 없이 G1부터 기계적으로 다시 만들면 남의 작업을 버리고, 반대로 무비판적으로 살리면 하류 게이트에서 더 비싸게 터진다.

## 1. 절단면은 게이트가 아니라 산출물이다

게이트(G1/G2/G3)는 **승인 단위**이지 판정 단위가 아니다. G2 안에는 성격이 전혀 다른 산출물이 섞여 있다.

| 산출물 | 만드는 주체 | 재생성 비용 | 판정 대상? |
|---|---|---|---|
| static 단일파일 | 스크립트 | 초 단위 | ❌ |
| **IR JSON** | 스크립트(브라우저 실측) | 화면당 수 초 | ❌ |
| 보드 HTML · PNG · bundle · placement | 스크립트 | 분 단위 | ❌ |
| 화면 HTML | 사람 | 화면당 수 시간 | ✅ |
| **디스크립션 본문** | 사람/AI + 정책 대조 | 화면당 수 시간 | ✅ |
| Screen ID 채번 · 매니페스트 메타 | 사람 | 중간 | ✅ |

### 규칙 1 — 결정론적 산출물은 판단하지 말고 재생성한다

남의 IR을 신뢰할 이유가 없다. 값이 싸고, 규격 일치가 전부이며, 재생성해야 하류의 좌표계가 맞는다. 여기서 "재사용할까"를 고민하는 것 자체가 손해다.

### 규칙 2 — 사람 판단이 들어간 것만 판정한다

실제 질문은 하나로 줄어든다: **기존 화면 HTML과 디스크립션을 살릴 수 있는가.**

## 2. 살릴지 말지 — 결손의 종류로 가른다

계약([../contracts/](../contracts/))에 미달할 때, **미달의 종류**가 답을 정한다. 비용을 눈대중으로 비교하지 않는다.

| 결손 종류 | 무엇인가 | 예 | 판정 |
|---|---|---|---|
| **표기 결손** | 기계 변환이 가능한 차이 | 필드명 불일치, 문장부호 금칙 위반, ※행 순서, 색 표기 방식 | **이행** — 변환기를 한 번 쓰면 전량 처리 |
| **구조 결손** | 사람 판단을 다시 해야 하는 차이 | 행 분해 단위가 화면 영역과 안 맞음, 콜아웃 대상 셀렉터 부재, 영역 넘버링 없음 | **재작성** — 변환으로 못 메운다 |
| **원천 결손** | 근거를 추적할 수 없음 | 서술의 정책 근거가 어느 문서에도 없음 | **원천 확보 선행 후 재작성** — 이행하면 근거 없는 문장이 그대로 Figma로 간다 |

`probe_inputs.mjs --descriptions <폴더>`가 콜아웃 보유율을 재서 표기/구조 어느 쪽인지 1차 신호를 준다.

## 3. 판정을 논쟁하지 말고 파일럿으로 실측한다

**이 판정의 정답은 회의가 아니라 실행이다.**

기존 산출물 **3건**을 골라 계약에 넣고 실제로 끝까지 돌린다.

```bash
lint_descriptions → build_board → capture_boards
```

| 결과 | 판정 |
|---|---|
| 전부 통과 | **이행 경로.** 변환기를 만들어 전량 처리 |
| 콜아웃 미발견·빈 행으로 실패 | **구조 결손 확정.** 재작성 |
| 통과했으나 보드를 보니 영역 분해가 화면과 안 맞음 | **재작성.** 기계는 통과시켜도 사람이 못 읽는다 |

한 화면 30분 투자로 화면군 전체의 방향이 결정된다.

**표본 고르는 법** — 가장 단순한 화면 1건, 가장 복잡한 화면 1건, 부속(모달)이 있는 화면 1건. 쉬운 것만 고르면 통과하고 나서 확산 단계에서 터진다.

## 4. 상류를 다시 만들어야 하는 경우

> "이미 있는 G3 구동을 위해 G1·G2를 재생성하는 게 맞는 경우는 언제인가"

**하나뿐이다 — 기존 산출물이 다른 보드 규격으로 만들어졌을 때.** 다른 템플릿으로 이미 Figma 보드를 그려놨다면 엔진이 그것을 먹지 못한다. 이때는 상류부터 다시 만든다.

그 외에는 항상 **"살릴 건 살리고, 싼 건 재생성"**이다.

## 5. 판정 선언

판정 결과를 아래 표로 남긴다. 게이트를 건너뛰는 게 아니라, **게이트별로 방침을 선언하고 그 근거를 기록**하는 것이다.

```markdown
## 진입 판정 (YYYY-MM-DD)

| 산출물 | 방침 | 근거 |
|---|---|---|
| 화면 HTML | 이행 | 52화면 존재, 프로브 결과 렌더 성공·콘솔 오류 0 |
| static 변환 | 신규 | 외부 CSS 3건 미인라인 — 01-static 필요 |
| IR | 재생성 | 결정론적 산출물 |
| 디스크립션 | 재작성 | 파일럿 3건 중 3건 콜아웃 미발견 = 구조 결손 |
| Screen ID | 신규 채번 | IA에 ID 열 없음 |
| 보드·번들 | 재생성 | 결정론적 산출물 |

파일럿 실측: <리포트 경로>
```

`재작성`으로 선언한 항목이 하나라도 있으면 그 게이트는 정상 승인 절차를 거친다. 전부 `이행`/`재생성`인 게이트는 **파일럿 결과를 승인 근거로 삼아 한 번에 통과시킬 수 있다.**

## 6. 하지 말아야 할 단축

- **파일럿 없이 "품질이 좋아 보이니 이행"** — 보드를 만들어 보기 전에는 알 수 없다
- **콜아웃 매핑을 나중으로 미루기** — 콜아웃 없는 디스크립션은 보드가 안 나온다. 미루면 G3에서 전량 되돌아온다
- **IR을 남에게서 받기** — 규격·좌표계가 다르면 조용히 어긋난다. 재생성이 싸다
- **게이트 승인을 통째로 생략** — 방침 선언과 근거 기록까지 생략하면 나중에 왜 그렇게 했는지 아무도 모른다
