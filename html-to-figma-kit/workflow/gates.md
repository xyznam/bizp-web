# 게이트 — 3단계 승인

```
G0  진입 판정   프로브 → 진단표 → 정책 작성 → 방침 선언 → 파일럿 실측      ▶ 승인
G1  화면 생성   요구사항 확인 → HTML 작성/확보 → static 변환 → 렌더 검증    ▶ 승인
G2  보드 생성   IR 추출·검증 → 디스크립션 작성·린트 → 보드 빌드·캡처        ▶ 승인
G3  Figma 반영  번들 생성 → 픽셀 대조 → 플러그인 실행                       ▶ 완료
```

**각 게이트에서 멈추고 승인을 받은 뒤 다음으로 넘어간다. 한 번에 끝까지 돌리지 않는다.**

G0에서 `이행`으로 선언된 게이트는 파일럿 결과를 근거로 한 번에 통과시킬 수 있다([entry-triage.md](entry-triage.md) §5).

---

## G0 — 진입 판정

```bash
node <키트>/engine/scripts/probe_inputs.mjs \
  --screens <화면 폴더> --descriptions <기존 디스크립션 폴더> \
  --sample 3 --out output/reports/probe.md
```

**통과 조건**

```
□ 프로브 리포트 생성
□ ADAPTATION.md 진단표 전항 기재 (모름은 '모름'으로 기재, 공란 금지)
□ board-policy.json 작성 — TODO 잔존 0
□ 원천 슬롯 배정표 작성 (spec/policy-mapping.md §1)
□ 진입 판정 선언표 작성
□ 파일럿 3건 실측 완료
□ 반응형이면 보드 규격 결정 완료 (spec/board-template.md §7)
```

## G1 — 화면 생성

**이미 화면이 있으면 대부분 이행이다.** 없거나 새로 만들 때만 작성 단계가 실제로 돈다.

1. **요구사항 확인** — 원천 슬롯 B/C/D에서 해당 화면 항목을 뽑는다. 신규 화면이라 문서에 없으면 그 사실을 기록하고 사용자 입력을 원천으로 삼는다
2. **HTML 작성/확보** — 기존 화면 하나를 골격으로 삼아 그 화면군의 공통 셸 구조와 클래스 체계를 따른다
3. **내비게이션 등록** — 화면 목록/내비 데이터에 항목 추가
4. **static 변환** — [../contracts/01-static.md](../contracts/01-static.md)
5. **검증** — 브라우저로 열어 콘솔 오류 0, 내비 렌더, 모달·필터 동작, 레이아웃 확인

**통과 조건**

```
□ 대상 화면 전량 static 변환 완료
□ 콘솔 오류 0 · 요청 실패 0
□ 부속 화면(모달·드로어)이 트리거로 동작
□ probe 재실행 시 '읽을 수 없는 스타일시트' 0
□ 원본 편집 정본 무수정 (수정이 필요했다면 사본에)
```

**보드에 실리지 않는 것** — `boardStrip.selectors`에 등록한 프로토타입 전용 블록은 추출 단계에서 DOM 제거되므로 넣어도 되고 안 넣어도 된다. 화면 정의는 디스크립션으로 간다.

## G2 — 보드 생성

1. **IR 추출·검증** — [../contracts/02-ir.md](../contracts/02-ir.md)
2. **디스크립션 작성·린트** — [../contracts/03-description.md](../contracts/03-description.md)
3. **매니페스트 작성** — [../contracts/04-manifest.md](../contracts/04-manifest.md)
4. **보드 빌드·캡처** — [../contracts/05-figma.md](../contracts/05-figma.md) 1~4단계

**통과 조건**

```
□ IR 토큰 매핑률 ≥ 게이트값
□ lint_descriptions 위반 0
□ 보드 폭 정확 · 가로/세로 오버플로 0
□ 콜아웃 번호 ↔ 디스크립션 Num 1:1 · 빈 행 0 · 콜아웃 미발견 0
□ 콘솔 예외 0 · 자산 요청 실패 0
□ label·screenId 중복 0
□ figma-placement.json 좌표가 누적 규칙과 일치
```

**확산 절차 (파일럿 통과 후)**

1. 골드 스탠다드를 정한다 — 파일럿에서 만든 보드 중 가장 잘 나온 것
2. 디스크립션 작성은 **화면당 1작성자 fan-out**. 골드를 기준으로 삼는다
3. 화면별 build+capture 병렬 실행 → `merge_placements`로 전역 placement 병합
4. **적대 검증 fan-out** — 요구사항 정합 / 미결 커버리지 / 화면 사실 대조 / 콜아웃 시각. 결함 발견 시 해당 화면만 재생성

## G3 — Figma 반영

[../contracts/05-figma.md](../contracts/05-figma.md) 5~6단계 + 플러그인 실행.

**통과 조건**

```
□ 픽셀 대조 평균이 프로젝트 기준선 이상
□ 최상위 레이어 수 = 보드 수
□ 레이어명·좌표·크기 = placement 일치
□ Variables 바인딩 표본 확인
□ 백업 페이지 존재·무변경
```

**배치 판단** — 기존 그룹 파일에 새 페이지로 추가할지, 전용 파일을 신설할지는 사용자가 정한다. 번들이 계위 좌표를 싣고 플러그인이 좌상단을 (0,0)으로 평행이동하므로 신규분만 실행해도 어긋나지 않는다.

## 게이트를 넘지 못했을 때

**되돌아간다.** 하류에서 우회하지 않는다.

| 증상 | 진짜 원인이 있는 곳 |
|---|---|
| 토큰 매핑률 낮음 | G1 (static 미완) |
| 콜아웃 미발견 | G2 디스크립션 (셀렉터가 IR에 없음) 또는 G1 (화면 구조 변경) |
| 픽셀 대조 낮음 | G1 (폰트) 또는 정책 (`controls`) |
| 부속이 빈 상태로 캡처 | 정책 `domContract.triggerGroups` |
| 보드 폭 초과 | 정책 `board.designWidth` 또는 화면 폭 |
