# HTML → Figma UID 보드 키트

기획된 화면(HTML 프로토타입)을 **UID 보드**로 만들어 Figma에 네이티브 노드로 넣는 파이프라인입니다. 보드는 왼쪽에 화면, 오른쪽 420px에 정책·로직 디스크립션 표가 붙은 설계서 형식입니다.

어드민 화면군 47실화면·188보드를 실제로 이 파이프라인으로 만들어 Figma까지 보냈고, 그 구조를 다른 화면군에도 쓸 수 있게 정리한 것이 이 키트입니다.

## 무엇을 받는 건가

**완제품 도구가 아니라 파이프라인 구조 + 계약 + 검증된 레퍼런스 구현**입니다.

화면군마다 UI/GUI 디자인 규칙, 자산 구조, 정책 문서 체계가 다릅니다. 그래서 이 키트는 "실행하면 되는 프로그램"이 아니라, **AI가 읽고 자기 인풋 상황에 맞게 변형해 쓰는 재료**로 만들어져 있습니다.

| 계층 | 내용 | 손대는 정도 |
|---|---|---|
| `spec/` | 보드 규격·디스크립션 작성 규칙 | 그대로 씀 |
| `engine/` | 보드 조립·캡처·번들·검증·Figma 플러그인 | 그대로 씀 |
| `adapters/` | IR 추출기 + 정책 템플릿 | **설정값을 채워 씀** |
| `contracts/` | 단계별 입출력 스키마·통과 조건 | 지켜야 할 계약 |
| `examples/admin-v3/` | 어드민 실제 구현·완성 산출물 | 골격으로 참고 |
| `workflow/` | 게이트·진입 판정·규칙 역류 | 절차로 따름 |

## 준비물

| 항목 | 필수 | 없으면 |
|---|---|---|
| 화면 HTML (화면군) | ✔ | 시작 못 함 |
| Node.js + Playwright | ✔ | `npm i playwright` |
| Figma 데스크톱 앱 | ✔ | 로컬 플러그인 실행 불가 → PNG 폴백(편집 불가) |
| 요구사항 문서 | | 요구사항 행 생략 |
| 공통 정책 문서 | | 화면에서 읽히는 것만 서술 |
| 미결 사항 대장 | | 미결 추적 수단을 새로 만들 것을 제안 |
| IA (화면 목록·경로·ID) | | 가안 ID 체계 |

**정책 문서가 없어도 시작할 수 있습니다.** 없는 슬롯은 비운 채로 두고 그 사실을 산출물에 기록하는 것이 이 파이프라인의 방식입니다. 억지로 채우면 근거 없는 서술이 Figma로 갑니다.

## 설치

키트 폴더에서 한 번만:

```bash
npm run setup
```

`playwright` 설치 + Chromium 브라우저 내려받기를 함께 합니다. 이미 다른 곳에 Playwright가 있다면 설치 대신 위치만 알려줘도 됩니다.

```bash
export UID_PLAYWRIGHT_DIR=/경로/to/node_modules를_담은_폴더
```

## 시작하기

### 1. 무엇을 가졌는지 확인

```bash
node <키트>/engine/scripts/probe_inputs.mjs --screens <화면 폴더> --sample 3 --out probe.md
```

CSS 변수, 레이아웃 셸 후보, 모달 패턴, 버튼 클래스, 반응형 신호를 리포트로 뽑습니다. 정책 파일이 없어도 동작합니다.

### 2. 진단표 채우고 정책 작성

[ADAPTATION.md](ADAPTATION.md) §2의 15개 항목을 프로브 리포트를 보며 채운 뒤, `adapters/board-policy.template.json`을 복사해 `TODO`를 해소합니다.

### 3. 진입 판정

**이미 만들어 둔 화면이나 디스크립션이 있다면** 다시 만들지 말지를 [workflow/entry-triage.md](workflow/entry-triage.md)로 정합니다. 핵심은 두 가지입니다.

- 스크립트가 만드는 것(IR·보드·번들)은 **판단하지 말고 재생성**한다. 재생성이 초 단위로 싸다
- 사람이 만든 것(화면·디스크립션)만 판정 대상이다. **결손이 표기 층위면 이행, 구조 층위면 재작성**

그리고 **판정은 회의로 정하지 말고 파일럿 3건을 실제로 돌려서 정합니다.** 한 화면 30분이면 화면군 전체의 방향이 결정됩니다.

### 4. 게이트대로 진행

[workflow/gates.md](workflow/gates.md) — G1 화면 생성 → G2 보드 생성 → G3 Figma 반영. 각 게이트에서 멈추고 승인을 받습니다.

## AI에게 맡길 때

`SKILL.md`가 AI용 지시서입니다. 키트 폴더를 가리키거나 `.claude/skills/`에 두면 AI가 이 절차를 따릅니다. 사람이 읽을 문서는 이 README와 `ADAPTATION.md`입니다.

## 알아둘 제약

| 항목 | 내용 |
|---|---|
| **다중 뷰포트** | **미설계 영역.** 단일 뷰포트 전제로 만들어졌습니다. 반응형 화면군은 보드 규격 결정이 선행 과제이며, 결정할 항목은 [spec/board-template.md](spec/board-template.md) §7에 정리돼 있습니다 |
| SPA·Shadow DOM | IR 추출기가 화면당 파일 1개 + 일반 DOM을 전제로 합니다. 해당하면 어댑터 포크가 필요합니다 |
| 픽셀 대조 기준선 | 프로젝트마다 다릅니다. admin-v3는 188보드 평균 98.0%였고, 새 화면군은 첫 파일럿 값이 기준선이 됩니다 |
| 폰트 | Pretendard 미설치 시 폴백되며 픽셀 대조 값이 떨어집니다 |

## 산출물

```
output/
├─ ir/            화면별 IR JSON (토큰 참조 보존 DOM 트리)
├─ descriptions/  화면별 디스크립션 JSON
├─ screens/       화면·부속 스크린샷
├─ boards-html/   보드 HTML
├─ boards/        보드 PNG + figma-placement.json
├─ figma/         bundle.json (플러그인 입력)
└─ reports/       프로브·린트·캡처·픽셀대조 리포트
```

## 원본과의 관계

이 키트는 `html-to-figma/`(어드민 v3 스킬)와 `html-to-figma-v4/`(증분 확장 포크)에서 재사용 가능한 부분을 뽑아 일반화한 것입니다. **원본은 수정하지 않았습니다.** 어드민 작업은 원본으로 계속 진행하고, 새 화면군은 이 키트로 시작하면 됩니다.
