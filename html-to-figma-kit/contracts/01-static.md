# 01. static 단일파일 변환 계약

**구현은 작업자가 쓴다.** 참고 구현: `examples/admin-v3/scripts/build_static.py`

## 왜 필요한가

IR 추출은 `file://`로 화면을 열어 DOM과 CSS 규칙을 읽는다. 그런데 **`file://`에서 외부 스타일시트는 불투명 출처라 `cssRules` 접근이 막힌다.** 외부 CSS를 그대로 두면 토큰 역매핑이 통째로 실패하고, 그것이 조용히 "토큰 0개"로 나타난다.

`probe_inputs.mjs`가 이 상황을 감지해 리포트에 경고를 적는다. 경고가 있으면 이 단계를 먼저 끝낸다.

## 입력

- 화면 편집 정본 HTML (외부 자산 참조 상태)
- 공통 CSS·JS 자산
- 내비게이션 데이터 (있는 경우)

## 출력

화면당 **외부 파일 의존이 없는 단일 HTML 1개.**

## 필수 요건

| # | 요건 | 확인 방법 |
|---|---|---|
| 1 | 모든 CSS가 `<style>`로 인라인 | 브라우저에서 `document.styleSheets`의 `cssRules`가 전부 읽힘 |
| 2 | 모든 JS가 `<script>`로 인라인, **로드 순서 보존** | 콘솔 오류 0 |
| 3 | 이미지·폰트는 인라인(data URI) 또는 허용 호스트 | 요청 실패 0 |
| 4 | 인터랙션 보존 (모달·필터·드로어가 실제로 동작) | 부속 화면이 트리거로 열림 |
| 5 | 화면 간 링크는 상대경로 `.html` 유지 | 링크 클릭 시 대상 파일로 이동 |
| 6 | JS가 그리는 영역(내비 등)을 **마크업에 사전 렌더** | JS 미실행 상태에서도 골격이 보임 |

**6번의 이유** — JS가 `innerHTML`로 덮어쓰므로 사전 렌더는 무해하고, JS 실행 전 캡처나 JS 실패 시에도 레이아웃이 무너지지 않는다.

## 구현 시 주의

- **출력 폴더의 기존 `.html`을 전량 삭제하고 재생성하는 구현은 위험하다.** 다른 사람이 만든 산출물까지 지운다. 대상 파일만 교체하는 방식을 기본으로 한다
- 인라인 시 종료 태그를 이스케이프한다: `</script>` → `<\/script>`, `</style>` → `<\/style>`. 안 하면 파서가 조기 종료된다
- 원본 폴더의 수기 자산(README, tools 등)은 보존한다

## 통과 조건

```
□ 대상 화면 전량이 단일 파일로 변환됨
□ 브라우저에서 열어 콘솔 오류 0
□ probe_inputs.mjs 재실행 시 '읽을 수 없는 스타일시트' 경고 0
□ CSS 변수 카탈로그가 실제 개수만큼 잡힘
□ 부속 화면(모달·드로어)이 트리거로 열림
□ 원본 편집 정본은 무수정
```

## 이미 단일 파일이라면

이 단계를 건너뛴다. 다만 **건너뛰기 전에 `probe_inputs.mjs`로 확인한다.** 단일 파일처럼 보여도 폰트나 아이콘이 외부 참조인 경우가 흔하다.
