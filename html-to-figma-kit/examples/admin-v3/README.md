# 레퍼런스 구현 — admin-v3

어드민 화면군을 이 파이프라인으로 **47 실화면 → 188 보드 → Figma 네이티브**까지 보낸 실물이다. 픽셀 대조 전량 평균 98.0%.

**베끼는 대상이 아니라 골격으로 삼는 대상이다.** 계약([../../contracts/](../../contracts/))을 지키면서 자기 인풋에 맞게 다시 쓴다.

## 이 화면군의 성격

| 항목 | 값 |
|---|---|
| 플랫폼 | 데스크톱 웹 어드민, **단일 뷰포트** |
| 화면 셸 | 좌측 고정 LNB(`.sidebar`) + 상단바(`.topbar`) + 본문(`.main`) |
| 화면 유형 | 목록형(조회조건 + 지표 + 표)이 다수, 폼형·대시보드형 소수 |
| 부속 화면 | 모달·드로어 (`.modal-backdrop > .modal`) |
| CSS 체계 | `:root` CSS 변수 토큰 (색 21종 + 치수 2종) |
| 정책 원천 | 마크다운 문서 3종 + IA 엑셀 |

## 파일

```
board-policy.json      전 항목이 채워진 정책 (domContract 포함)
scripts/
  build_static.py        01-static 구현 — assets 인라인 + LNB 사전 렌더
  build_manifest.mjs     04-manifest 구현 — IR 전량에서 자동 조립
  extract_policy.mjs     03-description 보조 — md 문서에서 화면별 항목 수집
gold/
  manifest-excerpt.json  아래 3보드의 매니페스트 항목
  main/                  메인 화면 보드 (01 회원 현황)
  aux/                   부속 모달 보드 (휴면 계정 복구)
  general/               공통 정의 보드 (G-07 목록 화면 공통 규칙)
```

**`scripts/`의 3개는 admin 전용이다.** 경로·문서 구조·LNB 데이터 형식이 박혀 있다. 새 화면군에서는 계약을 보고 다시 쓴다. 특히:

- `build_static.py`는 **출력 폴더의 `.html`을 전량 삭제하고 재생성한다.** 그대로 쓰면 남의 산출물까지 지운다
- `build_manifest.mjs`는 `<title>`을 챕터 정본으로, LNB 활성 항목을 경로로 쓴다. 그 규약이 없는 화면군에서는 다른 원천을 찾아야 한다
- `extract_policy.mjs`는 admin 마크다운의 헤딩 구조에 종속된다. 비구조화 문서라면 스크립트를 만들지 말고 AI가 직접 읽는다([../../spec/policy-mapping.md](../../spec/policy-mapping.md) §5)

## 골드 스탠다드 3유형

| 유형 | 폴더 | 매니페스트 `frame` | 디자인 영역에 그리는 것 |
|---|---|---|---|
| 메인 화면 | `gold/main/` | `main` | 화면 전체 스크린샷 + 콜아웃 |
| 부속(모달) | `gold/aux/` | `AD_AC_01_P02` (auxId) | 부속 프레임 스크린샷 + 콜아웃 |
| 공통 정의 | `gold/general/` | `general` | 스크린샷 없이 표·텍스트 직접 렌더 |

각 폴더에 `description.json`(우측 패널)과 `board.png`(완성 보드)가 있다. `gold/main/ir.json`은 메인·부속이 공유한다(부속은 IR의 `auxFrames[]` 안에 있다). `gold/general/general-blocks.json`이 General 보드의 디자인 영역 데이터다.

원천에서 디스크립션이 어떻게 도출됐는지는 [gold/SOURCE-TRACE.md](gold/SOURCE-TRACE.md).

## 이 프로젝트에서 나온 판단들

새 화면군에서 같은 갈림길을 만날 때 참고할 것.

| 갈림길 | admin의 판단 | 근거 |
|---|---|---|
| 부속 화면을 별도 보드로? | **분리.** 트리거 행에서 부속 Screen ID를 초록 참조 | 모달이 화면만큼 복잡해 한 보드에 안 들어감 |
| 여러 화면에 주입되는 공통 팝업 | **보드 1개만** 두고 각 화면에서 참조 | 13벌 중복을 1개로 통합해 보드 201 → 189 |
| 화면마다 반복되는 공통 정의 | **General 보드**로 단일화 | 14개 보드로 분리, 화면 보드는 참조만 |
| General 축 충돌 | **축별 정본 보드 고정** | 병렬 작성 시 같은 축을 두 보드가 정의하는 충돌이 실제로 발생 |
| 조건부 UI(라디오 분기 등) | 현행은 글 서술, **재검토 중** | 사용자가 "그 상태의 화면이 필요하다"고 지적 |
| Screen ID | **가안 채번** + 빨강 ※행에 기록 | IA에 정식 ID 열이 없음 |
