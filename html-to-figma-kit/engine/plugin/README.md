# Figma 반영 — 플러그인 사용법

**전 영역 네이티브다.** 디자인 영역(좌측 1500px)도 PNG가 아니라 프레임·텍스트 노드로 만든다.
헤더 2행·콜아웃·디스크립션 표·General 표는 이전부터 네이티브였다. 즉 보드 전체가 Figma에서
검색·수정·코멘트 가능하다.

PNG는 폴백으로만 남는다 (렌더 트리가 없는 보드, 또는 [디자인 영역을 PNG로] 체크 시).

## 준비 (1회)

1. **Figma 데스크톱 앱**을 설치하고 로그인한다. (웹 브라우저에서는 로컬 플러그인을 등록할 수 없다)
2. **Pretendard 폰트를 설치한다.** → https://github.com/orioncactus/pretendard (무료·오픈소스)
   설치하지 않으면 Noto Sans KR로 폴백되고, 자간이 달라 **줄바꿈이 원본과 어긋난다.**
   설치 후 Figma를 재시작해야 폰트 목록에 잡힌다.
3. 테스트용 **빈 Figma 파일**을 새로 만들어 연다.
4. 메뉴 `Plugins → Development → Import plugin from manifest…` 에서 이 폴더의 **`manifest.json`** 을 고른다.

API 토큰·OAuth·앱 승인·스토어 게시는 전부 필요 없다. 로컬 개발 플러그인은 별도 인증이 없다.

## 실행 (2단계 권장)

`Plugins → Development → BizPlanet UID 보드 생성기` 실행 후 아래 순서로 한다.
문제가 생겼을 때 원인이 폰트·표 쪽인지 화면 렌더 쪽인지 바로 갈린다.

**1단계 — General (이미지 자체가 없는 보드)**
`output/figma/groups/General/bundle.json` 을 번들 칸에 넣고 [보드 생성].
표·텍스트가 전부 네이티브이므로 **폰트 로드, 표 열 폭, Auto Layout, ※행 색**을 먼저 검증한다.

**2단계 — 화면 그룹 (디자인 영역 네이티브)**
`output/figma/groups/공통 팝업/` 이 가장 작다(1보드). 여기서 먼저 확인한 뒤
`회원-권한/` 같은 큰 그룹으로 넘어간다. `bundle.json` 1개와 **PNG 전부를 한 번에 선택**해 [보드 생성].
PNG는 폴백용이라 네이티브가 정상이면 쓰이지 않지만, 누락 시 폴백이 막히므로 함께 넣는다.

두 단계 모두 `새 페이지를 만들어 배치`를 켠 상태로 실행한다.
무료 플랜은 파일당 페이지 수가 제한되므로 **그룹마다 Figma 파일을 새로 만든다.**

## 검수 항목

| # | 확인 | 기준 |
|---|---|---|
| 1 | 보드 크기 | 폭 1920px 정확, 높이가 콘텐츠에 맞게 늘어남 |
| 2 | **폰트** | 완료 메시지에 `폰트: Pretendard` 로 표시되는지. `폴백`이면 설치 필요 |
| 3 | **디자인 영역 네이티브** | 화면 요소를 클릭해 개별 선택·수정이 되는지 (이미지 한 장이 아니어야 한다) |
| 4 | **버튼 라벨** | `+ 회원 직접 등록`, `검색`, 상태 배지가 한 줄인지 (세로로 쪼개지면 실패) |
| 5 | **표** | 열 정렬 — 숫자·날짜 우측, 상태 배지 중앙, 텍스트 좌측 |
| 6 | 헤더 2행 | Chapter 회색·Screen Path 노랑·Web Admin 주황 칩·Screen ID 위치 |
| 7 | 콜아웃 | 주황 원형 칩과 브래킷이 서술한 영역 옆에 붙는지 |
| 8 | 디스크립션 표 | ※행 3색, 요구사항 셀, 번호 행의 굵은 제목 + 불릿, 빨강·초록 의미색 |
| 9 | 레이어명 | 보드 이름이 `01_회원현황` 등 라벨과 일치, 화면 내부는 원본 클래스명 |
| 10 | **계위 배치** | 화면 오른쪽에 그 화면의 부속 보드가 늘어서고, 하위 화면(50 회원 상세 등)은 한 칸 들여써져 있는지. 완료 메시지에 `배치: 계위`로 표시된다 |

## 배치 규칙

화면 하나가 가로 띠 하나를 차지한다. 부속 보드는 아래가 아니라 **오른쪽**으로 이어지고,
5개째부터 아래 줄로 넘어간다. 하위 화면은 부모 바로 아래에 한 칸 들여써서 놓는다.

```
01_회원현황            01__AD_AC_01_P02
    50_회원상세         50__EN_SUSPEND   50__EN_EDIT   50__EN_WITHDRAW  50__MEM_END
    53_회원등록         53__MB_COMPANY   53__MB_STORE  53__MB_CONFIRM   53__MB_DONE
02_대행사관리          02__CP_SUSPEND   02__CP_ACTIVATE  02__modalCompanyCreate
```

계위는 매니페스트의 Screen Path에서 얻는다 (`회원/권한 > 회원 현황 > 회원 상세` → 부모는 회원 현황).
간격과 줄바꿈 기준은 `board-policy.json`의 `layout`에서 바꾼다.

## 알려진 차이 (수정 대상 아님)

브라우저 위젯 크롬이라 재구성 대상이 아닌 것들이다.

- `<select>` 의 드롭다운 화살표 아이콘
- `<input type="date">` 의 표시 형식 — 원본 `01/01/2025`, 네이티브 `2025-01-01` (값은 동일)
- 체크박스·라디오의 네이티브 그림

## 확산 (테스트 통과 후)

LNB 그룹별로 파일을 나눈다. 그룹 세트는 아래로 재생성한다.

```bash
node scripts/build_figma_groups.mjs
```

각 그룹마다 위 절차를 반복하고, 완료 후 [contracts/05-figma.md](../../contracts/05-figma.md)의
검증 체크리스트로 확인한다. 기존 페이지가 있으면 날짜 백업 후 새 페이지에 쓴다.

## 플러그인을 돌리기 전에 렌더를 확인하려면

플러그인 없이 렌더 트리가 맞는지 볼 수 있다. 같은 명세를 HTML로 되그려 원본 캡처와 대조한다.

```bash
node scripts/verify_render_tree.mjs --bundle "output/figma/groups/회원-권한/bundle.json"
```

결과는 `output/reports/render-verify/<보드>.repro.png`.

## 주의

- 번들 JSON에는 이미지 바이트가 없다. PNG는 함께 선택해야 한다 (전량 base64로 넣으면 163MB가 되어 플러그인이 감당하지 못한다).
- 보드 Y 좌표는 플러그인이 순서대로 다시 누적한다. 그룹별로 나눠 실행하면 각 페이지가 0부터 시작한다.
- 원본 HTML·planning 문서는 이 과정에서 전혀 수정되지 않는다.
